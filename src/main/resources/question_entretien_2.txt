PARTIE 1 : QUESTIONS SPRING BOOT
Q1 : Qu'est-ce que Spring Boot et pourquoi l'utiliser ?
Réponse :
Spring Boot est un framework qui facilite la création d'applications Spring avec configuration automatique et serveur intégré.

Avantages :

✅ Configuration automatique : Spring configure les beans par défaut

✅ Serveur intégré : Tomcat, Jetty ou Undertow intégrés

✅ Starters : Dépendances pré-configurées

✅ Production-ready : Actuator, métriques, health checks

✅ Pas de code XML : Configuration Java uniquement

✅ Facile à déployer : Un simple JAR

Exemple :

java
@SpringBootApplication
public class Application {
    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}
Q2 : Quelle est la différence entre Spring Boot et Spring MVC ?
Réponse :

Spring Boot	Spring MVC
Framework complet	Module de Spring
Configuration automatique	Configuration manuelle
Serveur intégré	Nécessite un serveur externe
Démarrage rapide	Démarrage plus lent
Production-ready	Nécessite des configurations supplémentaires
Annotation @SpringBootApplication	Annotation @EnableWebMvc
Conclusion : Spring MVC est un module de Spring pour les applications web. Spring Boot est un framework qui utilise Spring MVC avec configuration automatique.

Q5 : Comment fonctionne la configuration automatique ?

PARTIE 2 : QUESTIONS JPA / HIBERNATE
Q11 : Qu'est-ce que Hibernate ?
Réponse :
Hibernate est l'implémentation la plus populaire de JPA (Java Persistence API).

Caractéristiques :

✅ Mapping objet-relationnel

✅ Gestion automatique des relations (OneToMany, ManyToMany)

✅ Cache (premier et deuxième niveau)

✅ Requêtes JPQL/HQL

✅ Optimistic Locking avec @Version

java
@Entity
@Table(name = "users")
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(unique = true, nullable = false)
    private String email;

    @OneToMany(mappedBy = "user", fetch = FetchType.LAZY)
    private List<Order> orders = new ArrayList<>();
}

Q13 : Qu'est-ce que le Lazy Loading et Eager Loading ?
Réponse :

Lazy Loading	Eager Loading
Charge à la demande	Charge immédiatement
Moins de requêtes au départ	Plus de requêtes au départ
Évite le surcharge	Peut causer le N+1
FetchType.LAZY (Défaut)	FetchType.EAGER
java
// Lazy Loading (défaut)
@OneToMany(fetch = FetchType.LAZY)
private List<Order> orders;  // Les orders sont chargés seulement quand on y accède

// Eager Loading
@ManyToOne(fetch = FetchType.EAGER)
private User user;  // Le user est chargé immédiatement
Recommandation : Utiliser Lazy Loading et JOIN FETCH pour les besoins spécifiques.

Q14 : Qu'est-ce que le Problème N+1 et comment le résoudre ?
Réponse :

Problème : 1 requête pour l'entité + N requêtes pour chaque relation.

sql
-- 🔴 MAUVAIS (N+1)
SELECT * FROM users LIMIT 10;  -- 1 requête

-- Pour chaque utilisateur (10 requêtes supplémentaires)
SELECT * FROM orders WHERE user_id = 1;
SELECT * FROM orders WHERE user_id = 2;
SELECT * FROM orders WHERE user_id = 3;
-- Total : 11 requêtes
Solutions :

JOIN FETCH

java
@Query("SELECT u FROM User u LEFT JOIN FETCH u.orders")
List<User> findAllWithOrders();
Entity Graph

java
@EntityGraph(attributePaths = {"orders"})
List<User> findAll();
Batch Size

properties
spring.jpa.properties.hibernate.default_batch_fetch_size=10
Q15 : Qu'est-ce que @Version (Optimistic Locking) ?
Réponse :
@Version permet de gérer les conflits de modification simultanée.

java
@Entity
public class User {
    @Id
    private Long id;

    @Version
    private Long version;  // Incrémenté à chaque modification
}
Fonctionnement :

text
1. Utilisateur A lit User (version = 0)
2. Utilisateur B lit User (version = 0)
3. A modifie et sauvegarde (version = 1)
4. B modifie et sauvegarde (version = 1) → Exception OptimisticLockException !
Pourquoi : Évite la perte de données en cas de modifications simultanées.

@OneToMany	@ManyToMany
Un parent a plusieurs enfants	Plusieurs parents ont plusieurs enfants
Table de jointure optionnelle	Table de jointure obligatoire
Exemple : Un utilisateur a plusieurs commandes	Exemple : Un utilisateur a plusieurs rôles

// ManyToMany (avec table de jointure)
@ManyToMany
@JoinTable(name = "user_roles")

Q17 : Qu'est-ce que JPQL ?
Réponse :
JPQL (Java Persistence Query Language) est un langage de requête orienté objet.

sql
-- SQL
SELECT u.id, u.email, u.nom FROM users u WHERE u.email = 'admin@example.com'

-- JPQL
SELECT u FROM User u WHERE u.email = 'admin@example.com'
Différences :

JPQL utilise les noms des entités, SQL utilise les noms des tables

JPQL est orienté objet, SQL est orienté table

JPQL est portable (fonctionne avec toutes les bases), SQL est spécifique

Q18 : Qu'est-ce que @Query ?
Réponse :
@Query permet d'écrire des requêtes JPQL ou SQL personnalisées.

java
@Repository
public interface UserRepository extends JpaRepository<User, Long> {

    // JPQL
    @Query("SELECT u FROM User u WHERE u.email LIKE %:keyword%")
    List<User> searchByEmail(@Param("keyword") String keyword);

    // NATIVE SQL
    @Query(value = "SELECT * FROM users WHERE email LIKE %:keyword%", nativeQuery = true)
    List<User> searchByEmailNative(@Param("keyword") String keyword);

    // Avec JOIN FETCH (optimisation N+1)
    @Query("SELECT u FROM User u LEFT JOIN FETCH u.orders WHERE u.id = :id")
    Optional<User> findByIdWithOrders(@Param("id") Long id);
}
PARTIE 3 : QUESTIONS SPRING SECURITY
Q19 : Qu'est-ce que Spring Security ?
Réponse :
Spring Security est un framework pour sécuriser les applications Spring.

Fonctionnalités :

✅ Authentification (Login/Register)

✅ Autorisation (Permissions/Rôles)

✅ Protection contre les attaques CSRF, XSS

✅ Support JWT

✅ Intégration facile avec Spring Boot

java
@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable())
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/auth/**").permitAll()  // Public
                .anyRequest().authenticated()                 // Protégé
            )
            .addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter.class);
        return http.build();
    }
}

Q21 : Qu'est-ce que UserDetailsService ?
Réponse :
UserDetailsService est une interface Spring Security pour charger un utilisateur.

java
@Service
public class CustomUserDetailsService implements UserDetailsService {

    private final UserRepository userRepository;

    @Override
    public UserDetails loadUserByUsername(String email) throws UsernameNotFoundException {
        User user = userRepository.findByEmail(email)
            .orElseThrow(() -> new UsernameNotFoundException("Utilisateur non trouvé"));

        // Construire les autorités
        Set<GrantedAuthority> authorities = user.getRoles().stream()
            .map(role -> new SimpleGrantedAuthority("ROLE_" + role.getName()))
            .collect(Collectors.toSet());

        // Retourner UserDetails
        return new User(
            user.getEmail(),
            user.getPassword(),
            user.isEnabled(),
            true, true, true,
            authorities
        );
    }
}

Q23 : Qu'est-ce que CSRF et comment le désactiver ?
Réponse :
CSRF (Cross-Site Request Forgery) est une attaque où un site malveillant envoie une requête à votre API en utilisant la session de l'utilisateur.

Pour les APIs JWT : On désactive CSRF car JWT est stateless et les sessions ne sont pas utilisées.

java
@Configuration

    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable())  // ✅ Désactiver CSRF pour les APIs JWT
            .authorizeHttpRequests(auth -> auth
                .anyRequest().authenticated()
            );
        return http.build();
    }
}

PARTIE 4 : QUESTIONS JWT
Q25 : Qu'est-ce que JWT ?
Réponse :
JWT (JSON Web Token) est un standard pour l'authentification sans état.

Structure :

text
xxxxx.yyyyy.zzzzz
Header.Payload.Signature
1. Header (Algorithme et type) :

json
{
  "alg": "HS256",
  "typ": "JWT"
}
2. Payload (Données) :

json
{
  "sub": "user@email.com",
  "iat": 1234567890,
  "exp": 1234567890,
  "roles": ["ROLE_USER"]
}
3. Signature (Vérification) :

java
HMACSHA256(
  base64UrlEncode(header) + "." + base64UrlEncode(payload),
  secret
)
Q26 : Quelle est la différence entre JWT et JWS ?
Réponse :

JWT	JWS
JSON Web Token (format)	JSON Web Signature (sécurité)
Contient des claims (données)	Contient une signature
Peut être non signé	Toujours signé
header.payload	header.payload.signature
Exemple :

JWT : xxxxx.yyyyy (non signé, pas sécurisé)

JWS : xxxxx.yyyyy.zzzzz (signé, sécurisé)

Dans la pratique : On utilise toujours JWS (JWT signé).

Q27 : Comment fonctionne JWT dans votre projet ?
Réponse :

java
// 1. Génération
@Component
public class JwtTokenProvider {

    public String generateToken(Authentication authentication) {
        UserDetails userDetails = (UserDetails) authentication.getPrincipal();
        String email = userDetails.getUsername();

        return Jwts.builder()
            .setSubject(email)
            .setIssuedAt(new Date())
            .setExpiration(new Date(System.currentTimeMillis() + 864000000)) // 10 jours
            .signWith(getSigningKey(), SignatureAlgorithm.HS256)
            .compact();
    }

    // 2. Validation
    public boolean validateToken(String token) {
        try {
            Jwts.parserBuilder()
                .setSigningKey(getSigningKey())
                .build()
                .parseClaimsJws(token);
            return true;
        } catch (Exception e) {
            return false;
        }
    }
}

Q29 : Comment rafraîchir un token JWT ?
Réponse :
La méthode la plus courante est d'utiliser un Refresh Token.

java
@RestController
public class AuthController {

    // 1. Login → Access Token + Refresh Token
    @PostMapping("/login")
    public ResponseEntity<TokenResponse> login(@RequestBody LoginRequest request) {
        String accessToken = tokenProvider.generateToken(authentication);
        String refreshToken = tokenProvider.generateRefreshToken(authentication);
        return ResponseEntity.ok(new TokenResponse(accessToken, refreshToken));
    }

    // 2. Refresh → Nouvel Access Token
    @PostMapping("/refresh")
    public ResponseEntity<TokenResponse> refresh(@RequestBody RefreshRequest request) {
        String refreshToken = request.getRefreshToken();
        if (tokenProvider.validateRefreshToken(refreshToken)) {
            String newAccessToken = tokenProvider.refreshAccessToken(refreshToken);
            return ResponseEntity.ok(new TokenResponse(newAccessToken, refreshToken));
        }
        throw new RuntimeException("Refresh token invalide");
    }
}
Q30 : Comment gérer la révocation d'un token JWT ?
Réponse :
JWT est stateless, donc la révocation est difficile.

Solutions :

Blacklist (Redis/Base de données)

java
@Service
public class TokenBlacklist {

    @Autowired
    private StringRedisTemplate redisTemplate;

    public void blacklistToken(String token) {
        long expiration = tokenProvider.getExpiration(token);
        redisTemplate.opsForValue().set("blacklist:" + token, "true", expiration, TimeUnit.MILLISECONDS);
    }

    public boolean isBlacklisted(String token) {
        return redisTemplate.hasKey("blacklist:" + token);
    }
}

PARTIE 5 : QUESTIONS CACHE
Q31 : Qu'est-ce que le cache et pourquoi l'utiliser ?
Réponse :
Le cache est un stockage temporaire de données pour améliorer les performances.

Avantages :

✅ Réduction du temps de réponse (de 100ms à 1ms)

✅ Réduction de la charge sur la base de données

✅ Meilleure scalabilité

Types de cache :

Local (Caffeine, Ehcache) : Rapide, mais pas partagé

Distribué (Redis, Hazelcast) : Partagé, mais plus lent

Hybride (Local + Redis) : Le meilleur des deux mondes

Q32 : Quelle est la différence entre Cache MISS et Cache HIT ?
Réponse :

text
Cache MISS : Donnée PAS dans le cache
    Client → Cache (vide) → Base de Données → Cache (stocke) → Client
    Temps : 100ms

Cache HIT : Donnée DANS le cache
    Client → Cache (donnée présente) → Client
    Temps : 1ms
Exemple pratique :

java
// 1er appel : Cache MISS (va en BDD)
getUser(1) → 🔴 Cache MISS → BDD → Cache (stocke)

// 2ème appel : Cache HIT (vient du cache)
getUser(1) → ✅ Cache HIT → (pas de BDD)
Q33 : Qu'est-ce que Caffeine ?
Réponse :
Caffeine est une implémentation de cache Java performante.

Fonctionnalités :

✅ Extrêmement rapide (en mémoire)

✅ Gestion automatique de l'expiration

✅ Limitation de taille

✅ Statistiques intégrées

✅ Éviction intelligente (LRU)

java
@Configuration
@EnableCaching
public class CacheConfig {

    @Bean
    public CacheManager cacheManager() {
        CaffeineCacheManager cacheManager = new CaffeineCacheManager();
        cacheManager.setCaffeine(Caffeine.newBuilder()
            .expireAfterWrite(10, TimeUnit.MINUTES)  // 10 minutes
            .maximumSize(1000)                       // 1000 entrées
            .recordStats()                           // Statistiques
        );
        return cacheManager;
    }
}

Q35 : Qu'est-ce que le modèle MVC ?
Réponse :

text
┌─────────────────────────────────────────────────────────────┐
│  CONTROLLER (Contrôleur)                                   │

│  VIEW (Vue)                                                │

│  - Affichage des données                                   │
└─────────────────────────────────────────────────────────────┘
Dans Spring Boot :

Controller = @RestController

Model = @Entity + @Service

View = JSON (pour les API REST)

PARTIE 7 : QUESTIONS CODE
Q36 : Qu'est-ce qu'un DTO ?
Réponse :
DTO (Data Transfer Object) est un objet qui transporte des données entre les couches.

java
// Entité (base de données)
@Entity
public class User {
    private Long id;
    private String email;
    private String password;  // Sensible
    private LocalDateTime createdAt;
}

// DTO (API)
public class UserResponseDTO {
    private Long id;
    private String email;
    private LocalDateTime createdAt;
    // ✅ Pas de password
}
Pourquoi :

✅ Sécurité : Cache les champs sensibles

✅ Performance : Charge moins de champs

✅ Découplage : L'entité peut évoluer sans impacter l'API

public class UserMapper {

        user.setPassword(dto.getPassword());

@Service
@Transactional  // Au niveau de la classe
public class UserService {

    @Transactional(readOnly = true)  // Lecture seule

    @Transactional  // Modifie les données
    public User createUser(User user) { ... }

    @Transactional(rollbackFor = Exception.class)  // Rollback sur Exception
    public void transfer(Account from, Account to, BigDecimal amount) {
        from.debit(amount);
        to.credit(amount);
        if (amount > 1000) {
            throw new RuntimeException("Montant trop élevé");  // Rollback
        }
    }

Q43 : Comment gérer les exceptions ?
Réponse :

java
@RestControllerAdvice
public class GlobalExceptionHandler {

    // 404 Not Found
    @ExceptionHandler(ResourceNotFoundException.class)
    public ResponseEntity<ErrorResponse> handleNotFound(ResourceNotFoundException ex) {
        return ResponseEntity.status(HttpStatus.NOT_FOUND)
            .body(new ErrorResponse(ex.getMessage()));
    }

    // 400 Bad Request (Validation)
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ErrorResponse> handleValidation(MethodArgumentNotValidException ex) {
        Map<String, String> errors = new HashMap<>();
        ex.getBindingResult().getAllErrors().forEach(error -> {
            String fieldName = ((FieldError) error).getField();
            String message = error.getDefaultMessage();
            errors.put(fieldName, message);
        });
        return ResponseEntity.status(HttpStatus.BAD_REQUEST)
            .body(new ErrorResponse("Validation échouée", errors));
    }

    // 500 Internal Server Error
    @ExceptionHandler(Exception.class)
    public ResponseEntity<ErrorResponse> handleGlobal(Exception ex) {
        return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR)
            .body(new ErrorResponse("Une erreur interne est survenue"));
    }
}
